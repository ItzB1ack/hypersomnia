КОШМАР «КОРИДОР ПАЛАТ» — ПРОТОТИП ПЕТЛИ ЧЕРЕЗ IMMERSIVE PORTALS
База: ItzB1ack/hypersomnia, main @ 01e91aad2fcb09457eab118da048e54b17ef8ecf.
Только исходники/инструкция/патч. Готового JAR и полного репозитория нет.

ЧТО ИЗМЕНИЛОСЬ
- Два обычных портала Immersive Portals внутри уже существующей зоны ward в измерении снов. При движении вперёд портал возвращает на 24 блока назад, при движении назад — наоборот. Плоскости стоят на одинаковой фазе восьмиблочного рисунка и не пересекают двери палат. Глобальные порталы измерения не меняются.
- Счётчик проходов вперёд индивидуален, хранится в данных сна, сбрасывается при выходе; сам по себе не запускает изменения кошмара. Переходы назад не увеличивают счётчик. Для теста: /hypersomnia_nightmare status.
- Пара сохраняется как сущности; UUID записаны в NightmareSavedData. Перед созданием проверяются готовность сущностей в обоих чанках и отсутствие порталов с собственными метками. При повреждённой/не найденной сохранённой паре повторное создание заблокировано. Не удалять данные или порталы наугад.
- При первом запросе после загрузки мира сущности чанков могут быть ещё не готовы: команда сообщает «not ready», нужно подождать и повторить /hypersomnia_nightmare enter ward. Существующий автоматический вход через DreamTransition.enterNightmare при неготовности места переключается на обычный сон; это важное ограничение прототипа, не обещание автоматического повторного входа.
- Изменены: DreamData.java, NightmareBuilder.java, NightmareCommand.java, NightmareSavedData.java, NightmareTuning.java, META-INF/neoforge.mods.toml. Добавлен WardLoopPortals.java. Нет изменений в прочих механиках и генерации обычного сна.

УСТАНОВКА ИСХОДНИКОВ
1. Сохраните резервную копию проекта и мира. Данный патч относится к указанной базе. Если файлы с тех пор менялись, не затирайте их: перенесите изменения вручную.
2. Из корня проекта проверьте: git apply --check CHANGES/ward-portals.patch
   Затем выберите один способ: git apply CHANGES/ward-portals.patch ИЛИ копирование содержимого src/ из архива в проект. Не используйте оба сразу.
3. Обязательно вручную добавьте в существующий корневой build.gradle (он не входит в архив по согласованному формату) следующие строки.
   Внутрь существующего repositories { ... }:
       maven {
           url = "https://api.modrinth.com/maven"
           content { includeGroup "maven.modrinth" }
       }
   Внутрь существующего dependencies { ... }:
       implementation "maven.modrinth:immersive-portals-neoforge:6.0.7"
       localRuntime "maven.modrinth:cloth-config:15.0.140+neoforge"
   Не создавайте вторые блоки, если удобнее добавить строки в уже существующие. Указанная база содержит конфигурацию localRuntime. Имя модового ID для metadata — imm_ptl. Для других версий сначала проверить совместимость, metadata сейчас требует [6.0.7,6.0.8).
4. Соберите обычным способом, например gradlew.bat build. В игре должны быть Immersive Portals NeoForge 6.0.7 и Cloth Config NeoForge для Minecraft 1.21.1 (проверенная сборочная версия Cloth Config 15.0.140). На сервере и у каждого клиента нужны совместимые зависимости. Это обязательная зависимость Hypersomnia: без IP мод не запустится, не только кошмар.
   Immersive Portals: https://modrinth.com/mod/immersive-portals-neoforge/version/6.0.7
   Cloth Config: https://modrinth.com/mod/cloth-config/version/15.0.140+neoforge

ПРОВЕРКА В ИГРЕ (НЕ ВЫПОЛНЯЛАСЬ)
- Только в отдельном тестовом мире/после резервной копии, с правами оператора. Первое построение коридора использует существующий строитель и изменяет блоки в зоне кошмара. Команда build ward принудительно ПЕРЕСТРАИВАЕТ её и может затереть блоки: для обычного теста её не используйте.
- /hypersomnia_nightmare enter ward — вход через текущую систему сна. Если «not ready», подождать и повторить; если сообщение повторяется постоянно, не удалять порталы и прислать описание/лог.
- Идти вперёд и назад, оглядываться до и после прохода; проверить стык пола/стен/света, дальнюю рекурсию и производительность, GUI, прохождение на бегу и без движения, особенно рядом с дверями палат. Эффект бесшовности и совместимость с шейдерами не подтверждены.
- /hypersomnia_nightmare status — проходы ВПЕРЁД увеличивают ward forward loops; назад не увеличивают. Счётчик индивидуален, не влияет на окружение. Старый /hypersomnia_nightmare tp ward не запускает полноценное состояние кошмара и для проверки счётчика не подходит.
- /hypersomnia_nightmare exit — выход через текущую логику пробуждения. Она может перемотать ночь и изменить усталость, как уже было до этого пакета. После выхода счётчик сбрасывается. Автовыход по текущему таймеру тоже остаётся.
- Проверить перезапуск мира, повторный вход, отсутствие дублей, взаимодействие с обычным сном, два игрока и dedicated server. Если порталы не готовы или повреждены, действовать по сообщению; не считать систему проверенной только по сборке.
