# HYPERSOMNIA — НОЧНАЯ СЕССИЯ: ПЛАН И ПРОМТ

> Как запускать: одно сообщение агенту —
> «Работай по `PROMTS/NIGHT_PLAN.md` до <время/цель>, коммить и пушь после каждой задачи».
>
> `PROMTS/ULTRAPROMT.txt` — источник истины и канон. Этот файл — исполняемый план ночи
> и журнал состояния. Если они расходятся, прав ULTRAPROMT, а расхождение пишется в журнал.

---

## 0. Шапка состояния (переписывать в каждом коммите)

| Поле | Значение |
|---|---|
| Дата старта | — |
| Дедлайн / цель | — (пусто = идти до конца списка) |
| HEAD на старте | — |
| Сейчас в работе | N1 |
| Сделано | 0 / 11 |
| Следующая | N1 |
| Блокеры | — |

Правило: шапка — единственная память, которая переживает сжатие контекста.
После компактизации первым делом читается шапка + раздел 2, и только потом код.

---

## 1. Стартовый ритуал (один раз, ~15 минут)

1. `git fetch origin main`, `git status`, `git log --oneline -5`. Записать HEAD в шапку.
   Незакоммиченные чужие правки не выбрасывать: если они не мои — спросить один раз,
   иначе отложить в `git stash` с записью в журнал.
2. Прочитать `PROMTS/ULTRAPROMT.txt` **не целиком**: разделы «Порядок», «Канон»,
   «Что осталось», «Правила работы». Остальное — по ключевым словам через grep.
3. Прочитать `PROMTS/PROMT_NEXT_CHAT.txt`: шапку, последнюю сессию, «ЧТО ОСТАЁТСЯ».
4. Прогнать baseline (раздел 3). Он должен быть зелёным. Если красный — это N0
   (чинить первым делом, до всех задач).
5. Начать N1.

## 2. Контракт автономной работы

- Работать непрерывно до конца списка или до реального блокера. Вопрос пользователю —
  только если без него нельзя двинуться (нет данных, нужно решение по канону, нужен запуск
  игры). Один вопрос за раз, коротко, по-русски.
- Одна задача = один связный набор правок = **один коммит = один push**.
  Не начинать следующую, пока предыдущая не закоммичена.
- `main` всегда должен собираться. Красное дерево запрещено.
- Минимальные точечные правки по якорям. Не переформатировать чужие файлы, не переименовывать
  без причины, не удалять незнакомый код — сначала разобраться.
- Комментарии и тексты в коде — по-русски, в стиле окружающего кода.
- Планы/итоги — в этот файл, а не только в чат.
- После сжатия контекста: читать шапку (раздел 0), текущую задачу и последний коммит.
  Не пытаться вспомнить весь чат.
- Субагенты разрешены и поощряются: `explore` — поиск по коду, `general` — параллельные
  аудиты. Коммитит и пушит только основной агент; результат субагента проверяется
  компиляцией, а не принимается на веру.
- Часы: в начале каждой задачи `Get-Date`. Если до дедлайна меньше ~30 минут — не начинать
  новую задачу, а закрыть текущую, обновить журнал и написать утренний отчёт.

## 3. Верификация (обязательный минимум)

Из корня проекта, всё офлайн:

```powershell
.\gradlew compileJava --offline
.\gradlew -I src\devtest\observer.init.gradle observerSelfTests --offline
.\gradlew -I src\devtest\lab.init.gradle labSelfTests --offline
.\gradlew -I src\devtest\ward.init.gradle wardSelfTests --offline
.\gradlew -I src\devtest\finale.init.gradle finaleSelfTests --offline
.\gradlew -I src\devtest\forest-reply.init.gradle forestReplySelfTests --offline
python src/devtest/check_resources.py
python src/devtest/check_network_sides.py
python src/tools/lab_check.py
```

Baseline 2026-11-10 (проверено, HEAD `886dd91`): всё зелёное —
`compileJava` (только старые deprecation-warnings), `observerSelfTests` (100),
`labSelfTests` (286 + 3 + 8 + 2839), `wardSelfTests` (110), `finaleSelfTests` (513),
`forestReplySelfTests` (15 + 90 + 36), `check_resources.py`, `check_network_sides.py`,
`lab_check.py`.

Важно: с `-q` Gradle не печатает `BUILD SUCCESSFUL`, поэтому успех проверять по
`$LASTEXITCODE` (должен быть 0), а не по тексту вывода.

Правила:
- После каждой задачи: `compileJava` + тесты, которых касается правка.
- Раз в ~2 задачи: весь набор.
- «Проверено» = компиляция + тесты + чекеры. **«В игре не проверено»** пишется всегда,
  пока пользователь явно не подтвердил обратное.
- Если тест упал не из-за моей правки — это блокер baseline: чинить или явно записать
  в журнал и не двигаться дальше, пока не понятно, что сломано.
- Новые self-tests складывать в `src/devtest/java/...` и подключать через
  `src/devtest/*.init.gradle` по образцу существующих.

## 4. Коммиты, пуш, промты

- Сообщение коммита — по-английски, первая строка ≤ 72 символов, тело: что и почему.
  В конце — `compileJava --offline passes; in-game look was not verified.` если это так.
- В тот же коммит:
  - `PROMTS/PROMT_NEXT_CHAT.txt` — новый пункт в текущей сессии или новая секция;
  - `PROMTS/ULTRAPROMT.txt` — затронутый раздел + строка «Обновлено»;
  - `CHANGES/*.txt` — для крупного блока (новая механика, сеть, NBT, ассеты);
  - шапка и журнал этого файла.
- `git push origin main` после каждого коммита. При отказе — `fetch` + `rebase`
  (не `force`, не переписывать историю).
- Косметику и переименования без смысла в промтах не упоминать.

## 5. Решения по умолчанию (не спрашивать)

| Ситуация | Решение |
|---|---|
| Геймплейное число, которое нельзя проверить без игры | оставить текущее, записать в журнал «кандидат на тюнинг» |
| Новый текст | сразу EN + RU; EN — в авторском стиле, не машинный перевод |
| Новый wire-формат | не менять; если без него нельзя — новый канал с версией, старый читается |
| Новая механика/класс/команда | пометить `[новое]`, обновить оба промта + `CHANGES/` |
| Неоднозначный баг | сначала воспроизводимый тест, потом фикс |
| Задача распухла | сузить до проверяемого куска, остаток — новый пункт `Nx.1` в журнале |
| Тест требует мира/игры | не эмулировать; пометить «нужна проверка в игре» и идти дальше |

## 6. Стоп-лист (ночью нельзя)

- `/hypersomnia_lab rebuild`, `resite` и любые команды, меняющие мир; правка `run/saves`.
- Визуальный и звуковой тюнинг «на вкус», баланс, который проверяется только игрой.
- Удаление ассетов, архивов, истории git; `push --force`, `rebase` чужих коммитов.
- Смена канона: лицо Норы, голос, авторские кадры концовок, природа осколка.
- Отключение проверок, `@SuppressWarnings` пачкой, «чтобы собралось».
- Client-only импорты в common, регистрация клиентских payload-хендлеров в common.
- Массовые рефакторинги «заодно».

## 7. Задачи

Порядок: N1 → N2 → N3 → N4 → N5 → N6 → N7 → N8 → N9 → N10 → N11.
Каждая задача заканчивается коммитом и пушем. Если задача упирается в игру — пропустить,
записать причину и взять следующую.

### N1. Baseline и расхождения промтов (30–60 мин)
Прогнать весь набор проверок. Сверить оба промта с кодом там, где названы классы, константы
и числа (`grep` по именам). Исправить только фактические расхождения: мёртвые ссылки,
устаревшие числа, «удалено/добавлено» не по коду.
**Готово, когда:** проверки зелёные; в промтах нет ссылок на несуществующие классы/константы.

### N2. Мультиплеер и состояние на игрока (2–3 ч)
Аудит: `ObserverProgressData`, `FatigueData`, `ChaseData`, `LabSavedData`, `SleepSceneState`,
`SleepSceneHandler`, память `HauntedTitle`. Искать: прогресс/усталость/флаги, живущие на
сервере глобально вместо игрока; поля без UUID; состояние, не сбрасываемое при выходе, смерти,
пробуждении; утечки между игроками при входе/выходе.
**Сделать:** минимальные фиксы найденного + тест на двух игроков (разные UUID, независимые
стадия/усталость/надписи) в `ObserverProgressSelfTest`.
**Готово, когда:** тест на двух игроков проходит и падает на старом поведении (проверить
временным откатом фикса).

### N3. Сохранения и рестарт (2–3 ч)
Все `SavedData`: `DATA_VERSION`, миграции, чтение старых NBT, устойчивость к отсутствующим
полям, дубликаты после рестарта, осиротевшие записи (`LiftRideStorage` и подобное).
**Сделать:** round-trip NBT и миграция со старой версии в тестах (`LabSavedDataSelfTest`
и/или новый); фиксы того, что не читается.
**Готово, когда:** старый NBT читается, повторное сохранение не плодит дубликаты.

### N4. Сеть: симметрия и гигиена (1.5–2 ч)
`check_network_sides.py` уже сверяет bridge/setup. Дополнить проверками: каждый payload
зарегистрирован на нужной стороне, у каждого есть хендлер, версия канала упомянута при
изменении формата, нет client-импортов и method reference в common/network.
**Сделать:** расширить чекер; убедиться, что он ловит искусственно сломанный кейс
(сломать → увидеть ошибку → откатить).
**Готово, когда:** чекер зелёный на `main` и красный на подменённом файле.

### N5. Тексты: паритет и плейсхолдеры (1–1.5 ч)
`check_resources.py` уже сверяет набор ключей EN/RU. Добавить: одинаковый набор
`%s`/`%d`/`%%` в обеих локалях, пустые значения, запрещённые `§k`/`§m` (если канон против
обманок), ключи без использования в коде — только предупреждением.
**Сделать:** расширить чекер, исправить найденные расхождения.
**Готово, когда:** чекер зелёный, новые правила описаны в промтах.

### N6. Логика концовок (2–3 ч)
`FinaleLogic`, `FinaleTexts`, `FinaleLogicSelfTest`: все концовки достижимы, порядок условий,
повторный вход, состояние после рестарта, fallback-тексты, отсутствие «залипания» на одной
ветке.
**Готово, когда:** тест покрывает каждую концовку и граничные условия; найденные дыры
исправлены.

### N7. Ward / Rounds / Session 47 (2–3 ч)
`WardScenarioSelfTest` и связанная логика: сценарии кошмаров, переходы, блокировки,
восстановление после выхода и рестарта.
**Готово, когда:** покрыты основные ветви; найденные баги исправлены.

### N8. Горячий путь кадра (1.5–2 ч)
Оверлеи и общие рисовальщики (`SleepSceneOverlay`, `TextSwarm`, `PixelDecay`, `ChaseOverlay`):
аллокации в кадре (`new`, `RandomSource.create`, конкатенации строк), лишние
`scissor`/`flush`, пересоздание объектов каждый кадр, лишние вычисления на пиксель.
**Сделать:** безопасные правки без изменения вида; где есть скрипт-превью — сверить картинку.
**Готово, когда:** в горячем пути нет новых объектов, вид не изменился.

### N9. Раскладка UI без игры (2 ч)
Вынести чистую математику раскладки (главное меню `HauntedTitle`, кнопки паузы, субтитры,
положение пары глаз) в функции без GUI и покрыть тестом: GUI scale 1..4,
1280×720 / 1920×1080 / 2560×1440 / 3840×2160 — ничего не пересекается, не выходит за экран,
минимальные размеры соблюдены.
**Готово, когда:** тест в `src/devtest` подключён через `*.init.gradle`; найденные пересечения
исправлены.

### N10. Чек-лист проверки в игре (1 ч)
Собрать все «НЕ ПРОВЕРЕНО» из `PROMT_NEXT_CHAT.txt` в `PROMTS/INGAME_CHECKLIST.md`:
система → шаги → команда → ожидаемый результат → приоритет. Ссылку добавить в оба промта.
**Готово, когда:** файл создан и покрывает все открытые пункты; утренний отчёт ссылается на него.

### N11. Резерв: багхант в затронутом (по остатку)
Прочитать изменённые за ночь файлы целиком, найти очевидные ошибки (границы массивов,
`null`, деление на ноль, неверные условия), исправить с тестом.
**Готово, когда:** нет незакоммиченных правок; каждая правка либо покрыта тестом, либо
объяснена в журнале.

## 9. Утренний отчёт (последнее сообщение ночи)

1. **Сделано:** список коммитов с одной строкой смысла на каждый.
2. **Проверено:** какие тесты/чекеры зелёные, что именно ими покрыто.
3. **Не проверено в игре:** список, со ссылкой на `PROMTS/INGAME_CHECKLIST.md`.
4. **Решения по умолчанию:** что выбрано без пользователя и почему.
5. **Блокеры:** что остановило и что нужно от человека.
6. **Дальше:** 2–3 следующих шага, если продолжать.
